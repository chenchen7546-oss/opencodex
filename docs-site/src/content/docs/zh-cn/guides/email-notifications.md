title: 邮箱通知（定制版）
description: Codex 账号需要重新认证时，通过 SMTP 向多个邮箱发送提醒。
---

定制版在侧边栏增加了**邮箱通知**。默认关闭，服务器需要能访问发信邮箱的 SMTP 服务。

## 配置发信账号与收件邮箱

1. 进入**邮箱通知**，填写邮箱服务商提供的 SMTP 服务器、端口、加密方式、用户名、授权码和发件邮箱。
   TLS 通常使用 465 端口，STARTTLS 通常使用 587 端口，始终校验服务器证书。
   QQ、163 等邮箱应按服务商要求开启 SMTP，并使用邮箱授权码。
2. 添加收件邮箱，最多 20 个，每个可独立启用或停用。邮件分别投递，收件人之间不会看到彼此的地址。
   保存后不会回显 SMTP 授权码；编辑其他配置时留空即可保留原值。
3. 点击**保存设置**，再点击已启用邮箱旁的**发送测试邮件**。即使总开关关闭，测试按钮也会向该邮箱
   发送一封真实测试邮件。显示“SMTP 已接收”后，请检查收件箱和垃圾邮件。
4. 打开**启用通知**并保存。开关和收件人编辑均在保存后生效。已经被系统确认的异常账号也会在下一次检查时提醒。

## 提醒规则

每分钟读取 OpenCodex 已经观察到的 Codex 账号状态，不额外调用模型、刷新令牌或查询额度。
此通知功能不会主动验证长期未使用的账号。访问令牌到期后自动刷新成功不触发提醒；
只有确认需要人工重新认证时才发送，包括缺少凭据、凭据被拒绝或无法继续刷新的情况，邮件包含实际原因。

同一个账号的同一次异常，向每个收件邮箱成功发送后不再重复，重启后仍保留记录。
账号恢复后再次异常会重新提醒。失败后每隔 15 分钟重试，最多尝试 3 次；极少数在 SMTP 接收邮件后、
本地记录成功前发生的崩溃，可能导致重复投递。**发送记录**显示最近 50 条结果，SMTP 接收不代表邮件一定进入收件箱。

配置与通知记录保存在 `$OPENCODEX_HOME/notifications/state.sqlite`，与账号、代理文件分开。
Docker 部署沿用现有 OpenCodex 状态卷。SMTP 直接使用服务器网络，不使用各账号绑定的代理。
此数据库包含 SMTP 授权码，备份时应按私密凭据保管。
